# tzreader

マルチフォーマット技術書リーダー（EPUB / PDF）。
仕様は [spec.md](spec.md)、実現可能性の検証結果は [spikes/findings.md](spikes/findings.md) と
[spikes/findings-windows.md](spikes/findings-windows.md) にある。

## ビルドと実行

```sh
./make-app.sh          # build/TZReader.app を作る（debug）
./make-app.sh release  # 最適化ビルド
open build/TZReader.app
```

テスト（手元の実 EPUB を使う。無い場合はスキップされる）:

```sh
swift test
```

実装間の検証（将来の Windows 版と振る舞いを揃えるため）:

```sh
cd conformance && bundle install && ./tzconf check
```

## 現状

- EPUB を展開せずに読む（ZIP の中央ディレクトリを読み、章を要求時に取り出す）
- リフロー型 EPUB の縦スクロール表示、目次（EPUB3 nav / EPUB2 NCX）
- 縦は読む・横は移動（← / → で前後の章とページ、右開きは左右反転）、章末に次の章への行き先
- PDF 表示（PDFKit）、アウトラインからの目次
- 固定レイアウト EPUB の表示（画像ページの判定、見開きの組み方、拡大とドラッグ）
- ページのサムネイル一覧（固定レイアウトと PDF。縮小読み込みで原寸まで復号しない）
- 並べ方の切り替え（連続スクロール／単ページ／見開き）とページの収め方（全体／横幅／原寸）
- 表示設定（文字サイズ、行間、本文幅、明暗テーマ、コード折り返し、出版社スタイル優先）
- CSS 互換レイヤー（`-epub-` プレフィックスを配信時に変換、原本は非破壊）
- 読書位置の保存と復元（fragment → 周辺テキスト → progression の順にフォールバック）
- 章内検索（部分一致、全角半角を区別しない、コード内かどうかを表示）
- しおり、戻る／進む履歴
- コードブロックのコピーと折り返し切り替え（ホバー時のボタン）
- 脚注リンクのポップオーバー表示（本文の位置を動かさない）と、内部リンクのホバープレビュー
- 複数ウィンドウ、⌘クリックで別ウィンドウ、書籍単位の共有層
- 書籍由来 JavaScript の無効化（アプリ注入スクリプトのみ動作）
- 書籍の診断（⌘⌥I）。欠落リソース、目次の参照先、CSS の互換変換、XML として不正な章を一覧する
- 検証用 CLI（`TZReader probe ...`）。診断と同じ内容を JSON で返す

未実装（spec.md の第 2 段階以降）:

- ハイライトとメモ
- 全文インデックス
- 新しいウィンドウの自動隣接配置

## 構成

```
Sources/TZReader/
├── App/          アプリ本体、ウィンドウ、メニュー
├── Document/     EPUB パーサ、BookDocument（書籍ごとの共有層）
├── Library/      蔵書と読書位置の保存
├── Model/        Locator、Publication などの形式共通モデル
├── Reader/       ナビゲータ（WebView / PDFKit）、スキームハンドラ、注入スクリプト
├── Search/       テキスト抽出と検索
├── Style/        CSS 互換レイヤー、表示設定
├── Support/      ZIP リーダー
└── UI/           SwiftUI ビュー
```

ナビゲータは目次・検索・位置表現を形式共通のプロトコルで扱い、サイドバーや履歴やライブラリは形式を意識しない。
新しい形式を足すコストは「ナビゲータ 1 枚と形式判定」に収まる。

## 設計上の決定

- **EPUB を展開しない。** ZIP から章を直接取り出して配信するため、開いてから最初の表示までにファイル展開の待ち時間が入らない。
- **元ファイルを書き換えない。** CSS の互換変換も文字コードの正規化も、配信の瞬間にメモリ上で行う。
- **読書時にネットワークを使わない。** 書籍内 JavaScript を無効化し、外部 URL は OS のブラウザへ渡す。
